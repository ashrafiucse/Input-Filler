# Residual Review Findings — Input Filler v1

Source: targeted multi-lens code review (correctness, testing, security/maintainability) following the ce-work build of `docs/plans/2026-08-03-001-feat-cross-browser-input-filler-plan.md`. The P1 and all real P2 findings plus security hardening were applied in commit `486590e`; the items below are the accepted, non-blocking P3 residuals.

## Accepted residuals (P3 — non-blocking)

- **`<select multiple>` not handled** — `src/lib/fillers.ts` `fillSelect` sets `el.value`, a no-op for multiple selects. Fix: set `option.selected` on one or more non-disabled options.
- **`datetime-local` / `month` / `time` / `week` value formats** — `src/lib/detect.ts` maps these to `'date'` and `generators.date()` emits `YYYY-MM-DD`, which these input types reject. Fix: generate the per-type format (or skip).
- **`data-fake` hints returned verbatim** — `src/lib/detect.ts` returns a hint like `firstName` as the logical type, but `orchestrate.generateValue` expects snake_case (`first_name`) and falls through to `dummyText`. Fix: normalize hints to snake_case (or accept both in `generateValue`).
- **Confirmation-copy scoping across forms** — `orchestrate.fillOne` keys the confirm value off the last value-bearing field across the whole `fillAllForms` pass. Across multiple forms a value field between a source and its confirm could be copied instead. Fix: track last value per logical type, or match the confirm to the nearest preceding same-type field.
- **`clipToWordBoundary` tiny-budget mid-word cut** — `src/lib/text.ts`: when `maxLen` is smaller than the first token, the slice has no space and is returned raw (e.g. `Manag`). Fix: return the first whole word (even if it exceeds `maxLen`) or empty when nothing fits.
- **Test-coverage gaps requiring browser mocks** — background `runOnActiveTab` gating/relay and `rebuildContextMenu` toggle are not unit-tested (they bind `browser.*` inline with no extracted seam). Cover by extracting an injectable seam or with `webextension` fakes.
- **Heuristic regex ReDoS guard** — `src/lib/regex-safety.ts` `isSafeRegex` rejects nested-quantifier, quantified-alternation, and large-count patterns, but it is still a heuristic; some evil shapes may slip through. Browsers cannot use `re2`, so production hardening would need a time-boxed execution wrapper (e.g. a Web Worker with a deadline) for user/imported regex.
